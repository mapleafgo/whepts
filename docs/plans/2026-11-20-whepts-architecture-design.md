# WhepTS 播放器架构改造方案

状态：已实施（`main`，1.2.0-next.0），验收进度见[验收记录](2026-11-20-whepts-acceptance.md)。本文保留方案正文与发布门槛，不记录实施过程。

## 决策与范围

保留 WebRTCWhep 的公开入口，采用**单一生命周期协调器 + 独立连接尝试 + 媒体控制**。改造的目标是让切流、重连和关闭有明确的资源归属，让调用方区分「连接已启动」与「画面已播放」。本轮不做 HLS/DASH 支持、不引入播放器框架或插件注册表、不承诺实现完整 WHEP 草案。不为了更换状态库或目录而重构。

依据：[跨协议播放器架构调研](2026-11-20-player-architecture-research.md)、[WHEP 协议与互通调研](2026-11-20-whepts-community-research.md)。从 Shaka 借鉴新请求优先和旧操作隔离；从 Video.js 借鉴换源与销毁分离；从 LiveKit 借鉴传输与播放分离；从 hls.js 借鉴分级恢复，不复制其共享事件总线。

| 方案 | 取舍 |
| --- | --- |
| 保留公开总线、逐处加守卫 | 改动小，但所有监听器、定时器和异步回调仍须各自遵守隐含顺序。 |
| **单一协调器，按资源划分生命周期** | 让状态提交和重连只有一个入口；旧网络 I/O 不阻塞切源，可直接用受控时序验证。 |
| 全局串行队列或通用播放器内核 | 串行等待会让新源被旧请求阻塞，仍需支持取消；插件化在没有第二种协议需求时增加接口成本。 |

## 播放器与调用方的职责

WhepTS 是单源播放器，不是故障切换或播放业务框架。播放器负责把调用方指定的 WHEP 流挂到指定元素，维护当前连接、执行播放控制、释放自己创建的资源，并通过状态和事件报告结果。业务决策不进入播放器。

| 场景 | 播放器 | 调用方 / 部署方 |
| --- | --- | --- |
| 播放、暂停与关闭 | 执行指令；保留显式暂停意图；只解绑自己仍拥有的流 | 提供元素，决定何时播放、暂停和关闭，管理页面与组件生命周期 |
| 浏览器禁止自动播放 | 报告 play:failed；不擅自静音、不重连 | 决定是否使用静音播放，展示提示并在用户手势中调用 resume |
| 同一地址的短暂故障 | 仅对已确认的传输故障有限重连；明确的元素故障只做局部恢复。耗尽后报告，不升级恢复范围 | 决定是否再试、换源或退出；不必复刻内部清理 |
| 源不可用、认证失败或协议不兼容 | 报告明确原因，不猜备用源、不刷新凭据、不切协议 | 选择地址、凭据、ICE 策略与备用流；部署方负责 CORS、代理配置和回收未取得句柄的会话 |
| 停滞与错误通知 | 流量停滞和无帧只报告，不改变连接状态，不诊断所有黑屏根因 | 决定展示、告警和业务兜底，不依赖 SDK 自动恢复画面 |

## 模块与依赖方向

| 模块 | 拥有 | 不做 |
| --- | --- | --- |
| 公开入口 | 构造配置、公开方法、状态读取和事件通知；构造时复制可变配置，集中解析默认值 | 不用公开事件触发内部动作，不持有远端会话字段 |
| 生命周期协调器 | 最新源意图、当前尝试引用、状态转换、唯一重连计时器与重连预算 | 不发 HTTP，不操作 DOM，不读取原始统计报告 |
| 连接尝试 | 不可变端点与凭据策略、取消信号、PeerConnection、ICE 候选队列、远端会话句柄；封装开始和幂等处置 | 不读全局播放器状态，不自行重连，不直接发公开事件 |
| 信令 | OPTIONS/POST/PATCH/DELETE、URL 解析、认证策略、响应判定 | 不管理播放器状态，不绑定元素，不盲目重试 POST |
| 媒体控制 | 借用的元素、当前流的挂载、用户暂停意图、可见性、局部恢复及其计时器 | 不改变连接，不删除调用方的元素或停止调用方的轨道 |
| 健康监控 | 按尝试采集播放和流量证据；同一种采样不重叠 | 不启动重连，不把统计不可用当成零流量 |

入口调用协调器；协调器调用具体的尝试和媒体模块。下游以返回值和私有回调上报结果。信令与媒体互不依赖。公开事件复用现有类型和事件库；不另造内部总线，也不为单一实现增加通用 transport 插件接口。编解码器探测是实例启动工作，不归任一 URL；只在仍存活时提交探测结果，并使用最新 URL 启动已有意图。

连接尝试负责启动和停止传输健康采样；媒体控制负责播放采样与可见性。协调器只启动或处置整个尝试，不编排 SDP、ICE 或原始 RTCStats，不操作元素。两类采样通过带尝试身份的结果上报，停止后丢弃在途结果。

## 扩展与维护规则

**扩展优先局部变化，而不是增加层数。** 保持入口薄、模块接口小，直接组合具体实现。只有出现第二种实际实现，且能用同一组行为测试验证两者的契约时，才考虑提取可替换接口；测试只替换 Fetch、时钟、PeerConnection、元素等外部副作用，不为每个类造一套接口。

| 变更场景 | 首选落点 | 不应被迫修改 |
| --- | --- | --- |
| 增加服务端兼容方式 | 信令模块解析差异，连接尝试选择协商步骤；默认配置由入口统一解析 | 媒体控制和重连机制 |
| 增加编解码器 | 编解码器模块的描述、探测与 SDP 生成 | 媒体控制、状态与重连 |
| 调整停滞或可见性判断 | 健康监控或媒体控制；仍通过既有私有回调上报结果 | 信令和会话清理 |
| 调整退避或重连预算 | 生命周期协调器；沿用同一个计时器和清理入口 | HTTP 客户端和媒体恢复逻辑 |

评审时按上表做变更演练：读者应能从入口直接追到资源的创建、使用和释放；任何状态只允许一个写入方；不能让所有模块都认识播放器内部状态。新增层如果只转发参数、不隐藏规则或资源管理，就保留直接调用。跨模块契约优先用可控时序测试验证，不靠测试私有字段证明正确。

## 生命周期与事件契约

- **状态**：保留公开五值。getting_codecs 表示初始化；running 表示当前尝试已启动，不等于 PeerConnection 连通或播放成功；restarting 表示已安排下一次尝试；failed 表示无自动恢复，仍可 updateUrl；closed 是终态。连接健康、实际播放、可见性和用户暂停是独立事实，不往公开状态枚举继续塞值。
- **切源**：先验证新 URL。无效地址发参数错误，不改变当前源、状态或已安排的重连；有效的同地址调用视为显式重试。有效命令作废旧尝试并取消已安排的重连，不修改调用方配置。探测未结束时只保留最新有效源；否则同步分离旧本地资源后立即启动新尝试，不等旧 I/O 或远端 DELETE。每个异步结果和定时器都须检查归属，旧结果只能清理自己的资源。
- **关闭**：先标记终态并撤销当前尝试身份，再取消请求和计时器、停监控、分离旧 PeerConnection、清候选、解绑本实例仍拥有的流，最后通知 close。重复调用无额外副作用。关闭后的 pause/resume 无操作，updateUrl 保留状态错误通知但不迁移状态。若读取到了旧尝试的会话地址，以独立、有界的清理请求尽力 DELETE，每个尝试只发一次。已分离的旧 PeerConnection 在 DELETE 结算或 5 秒期限到达时关闭；无可用会话地址则立即关闭。关闭通知与新尝试均不等待此过程。信令读到并校验响应头中的地址后立即交给该尝试登记，不等待 SDP 正文。迟到的响应若仍可读取地址，也只清理旧尝试。若取消使响应头不可读，则依赖服务端回收，不猜地址、不补发 POST。远端清理的失败不复活实例或驱动重连。
- **事件与重入**：先完成本地提交，再按下表通知。沿用同步 emitter 语义：已经开始派发的事件不撤回；监听器内切源或关闭只抑制后续旧事件。同步监听器抛错独立诊断，可能中断该事件的剩余监听器，但不阻断后续仍有效的通知，不进入信令错误路径。异步监听器自行处理 Promise 拒绝。移除监听器不改变内部流程。
- **超时与重连**：实例级探测有截止时间；超时清理探测资源，降级为不启用探测所得的扩展编解码器，并用最新有效源继续。连接尝试有建连截止时间，覆盖请求头、SDP 正文和应答后未连通；视频轨道到达和实际出帧由媒体模块分别判断。超时、主动取消和协议失败分开归类。取消或过时结果不通知连接错误；真实失败统一归一化为带阶段、可用 HTTP 状态码及 cause 的 WebRTCError。
- **重试与不确定结果**：同一尝试不重发 POST。记录 POST 未发出、已发出但结果未知、已登记远端句柄三种情形；最后一种按关闭规则清理，结果未知可能留下由服务端回收的旧会话。每个尝试以首次确认 PeerConnection connected 为界：此前的 ICE failed、信令失败或建连超时均结束尝试、清理并报告一次，不自动再排，即使该尝试来自重连。连通过后，只有当前 PeerConnection 进入 failed 或 disconnected 宽限到期且仍未恢复，才由协调器按预算重连同一源。阶段以当前尝试已提交的连通事实为准，不由超时与失败回调的到达顺序决定。POST 结果未知且无句柄时报告失败，交由调用方决定是否再试；认证、非法配置、不支持的信令不自动重试。预算耗尽时进入 failed，不继续排队；显式切源或确认传输健康且数据有进展才重置预算，不以进入 running 为准。传输 disconnected 先给有限宽限，恢复即撤销；failed 或宽限到期且复查仍不健康才上报。一次尝试只做一次重连决策。截止时间、宽限和预算集中在装配配置中，具体取值在实施计划确定。

| 已提交的动作 | 对外顺序 |
| --- | --- |
| 可恢复连接错误，已登记重连 | `state:change` → `error` → `restart` |
| 不再重试的连接错误 | `state:change` → `error` |
| 仅观测到流量停滞 | `flow:stalled`；无状态变化，不发 `restart` |
| 仅观测到播放无进展 | `play:stalled`；无状态变化，不重连 |
| 自动播放受阻、视频不可用或元素恢复耗尽 | `play:failed`；传输状态不变，由调用方决定下一步 |
| 当前播放请求的 `play()` 成功 | `play:success`；不代表已收到首帧 |
| 首次关闭并完成本地清理 | `state:change` → `close` |

每次发出非终态通知前检查对应的操作是否仍有效，不能用已被释放的尝试引用判断失败通知的有效性。监听器中关闭或切源会抑制尚未发出的旧故障通知；不会抑制已经提交的终态 `close`。仅在状态确实改变时发 `state:change`。

## 播放、互通和诊断

- 媒体控制按当前尝试聚合轨道，支持无关联 stream。连通后等待视频有独立的截止时间，不因音频先到立即拒绝；播放中短暂 mute 不立即重连，等视频超时或最后一条可用视频轨道 ended 时报告 `play:failed`，同一不可用期间不重复；收到有效替换轨道可正常挂载，在播放意图允许且 `play()` 成功后才发 `play:success`，不主动换源或为其建立额外恢复流程。仅当应播放且未被自动播放策略阻止时检查首帧和帧进展：仅在已有可用信号时报告无帧进展，不当作断流，不保证识别所有黑屏；局部恢复只对明确的元素故障执行，不重建连接；耗尽后发 play:failed，不再自行尝试播放，等待调用方 resume、切源或关闭。自动播放拒绝只报告 play:failed，等待调用方明确恢复。用户暂停跨切源、重连和可见性变化保持；resume 仍受懒加载可见性策略约束，暂停不关闭传输。
- 保留 `play:failed` 的英文 `reason` 和 `muted`，新增稳定 `code`：`autoplay-blocked`（浏览器要求用户操作）、`video-unavailable`（无视频或最后一条可用视频结束）、`element-recovery-exhausted`（局部恢复耗尽）、`playback-error`（其他播放失败）。调用方按 code 分支，不解析文案；首帧仍仅用于播放观测，不新增公开事件或状态。
- 一个元素只支持一个活跃播放器，宿主应先关闭旧实例再复用或替换元素。宿主更换已挂载的 srcObject 后，旧媒体控制停止写入，不抢回、不暂停、不静音、不清空新流。旧尝试或已经失去元素归属的 play() 结果不提交任何播放副作用。
- 流量监控按 inbound video report ID 比较增量；新/重置计数建立基线，失败或缺失不是零流量。统计采样有截止时间；若浏览器调用无法取消且仍未结算，不重叠发起同一采样，降级为连接状态和轨道信号并诊断统计不可用，其他监控继续。页面冻结、休眠或长采样间隔打断观察窗口，恢复时重建基线；不补算停滞。迟到的宽限定时器先检查当前传输，健康则不重连。保留单实例调度，区分任务耗时和采样间隔。
- WHEP 继续可兼容 MediaMTX 和 ZLMediaKit，但不把两者当成同一能力集。保留既有调用默认；提供可明确选择的全量 ICE 策略，供不支持 PATCH 的部署使用，收集超时作显式建连失败，不无界等待。Trickle 使用实际 MID、处理索引 0 和收集结束，按已验证的服务端策略处理 ETag。缺少可读 Location 时保留 201/SDP 兼容路径，标记会话不可管理、释放候选，不猜 URL、不补发 POST。没有足够互通证据前，不自动切换协议策略，不实现在原会话上 restartIce，也不把所有 406 误判为流不存在或反提议。
- 会话 Location 相对最终响应 URL 解析；校验目标协议及来源策略，配置凭据绑定初始端点来源；同源切流复用，跨来源切流及重定向不隐式转发。跨来源新目标需要凭据时以新配置创建实例，暂不扩展 updateUrl 签名。同源且受信任的会话请求复用既有认证策略。跨域响应头暴露、绝对 Location 经反代可达性需真实浏览器验收。
- 诊断带实例/尝试关联 ID、阶段、状态、耗时和原因，区分预期取消与故障；例行事件不上警告级别。诊断不得泄露 URL 查询凭据、Authorization、SDP、ICE 凭据或候选。生产包剥离控制台时，使用公开错误信息与可选诊断通道，不要求用户安装日志框架。

## 公开字段与诊断字段

新增 TypeScript 字段使用 camelCase，新增机器原因码使用小写短横线。保留已发布的事件名、字段名、状态字面量和 ErrorTypes 值；track/candidate 仍使用浏览器原生载荷，不统一包装。

| 契约 | 字段语义 |
| --- | --- |
| `Conf` | 保留已有字段名；`iceMode` 为可选配置，取 `trickle` 或 `complete`，省略时由装配处统一取 `trickle`。非法值作为配置错误，不静默回退。超时、宽限和退避仍为内部策略，不新增同义公开字段。 |
| `error` | 继续传 `WebRTCError`。`type` 沿用 `ErrorTypes`，`message` 为脱敏英文，仅供阅读。SDK 错误使用 `phase` 标识 `configuration`、`signaling` 或 `connection`；外部自行构造错误不必提供。只有读到实际 HTTP 状态码才提供数字 `httpStatus`；`cause` 可选，只保留脱敏摘要，不传原始异常或响应正文。 |
| `play:failed` | `code` 是上文定义的稳定原因码，`reason` 是英文说明，`muted` 是结果产生时元素的静音状态。调用方按 `code` 分支，不解析文案；兼容旧版本时允许回退到通用提示。 |
| 其他公开事件 | `state:change` 保留 `from` 和 `to`；`play:success` 保留 `muted`；停滞事件保留英文 `reason`，不增加重试标记。是否已安排重连以状态及 `restart` 为准。 |
| 可选诊断 | `playerId` 标识实例；`attemptId` 仅用于有归属的连接尝试，不等于远端会话地址；`elapsedMs` 仅在有计时范围时提供，使用单调时钟、毫秒单位。同义字段复用 `phase` 和 `httpStatus`；更细的 `operation` 留在诊断层。 |

可选字段无值时省略，不用空串或 0 冒充。公开错误与诊断使用同一脱敏规则。发布验收覆盖旧构造方式和监听器、字段类型、缺失语义、原因码分支，并核对类型、文档与实际事件一致。

## 迁移与验收

1. **生命周期**：首批交付能播放、切流和关闭的端到端路径，保留现有默认信令兼容方式；不是先拆空壳模块。先建立受控 Fetch/时钟/PeerConnection 的回归测试，再接入协调器与尝试处置。先验收 POST 已返回头但正文卡住时切源、两个监听器派发期间切源或关闭、短暂断网恢复后旧宽限定时器迟到；同时保留下表原有生命周期回归。断言旧资源不会释放 B，B 不等待旧 I/O，已知远端会话只 DELETE 一次。
2. **信令与编解码器**：明确认证与错误契约，补 MID/结束候选、重定向/Location/无 Location、错误正文和 ETag 用例；对齐 codec 描述和探测输入。两种固定服务端至少各验证一次播放、切流、关闭；真实浏览器覆盖不同源及 CORS、MediaMTX trickle、ZLMediaKit 全量策略。记录版本和限制，不用 mock 证明互通。
3. **媒体与监控**：覆盖无 stream、音频先到、暂停后可见性变化、旧 play/getStats 晚到、自动播放拒绝、统计缺失与多报告、重复停滞与恢复预算；在浏览器验收首帧、暂停恢复和关闭后解绑。
4. **发布**：保留公开导出和方法签名，明确兼容行为差异（流量停滞不再自动重连、自动播放被拒不再静音兜底）；构建不得改源码。使用实际 tarball 验证严格 NodeNext 和 bundler 消费入口、类型声明及包内容；运行 lint、类型检查、生产构建和回归测试后才发布。

## 既有审查问题：本次必须修复

下表是发布门槛，不是后续建议。每组问题在对应批次链接修复与验证证据；未验证保持开放，不能仅因模块替换而关闭。

| 编号 / 批次 | 基线问题 | 关闭条件 |
| --- | --- | --- |
| A1 生命周期 | 旧 OPTIONS、POST、PATCH、轨道或编解码器结果污染新会话；切流修改共享配置；关闭可能转回 failed；重入会留下重连计时器 | 受控延迟及监听器重入测试：无效地址保留旧流，同地址显式替换既有重连，仅最新源生效，共享/冻结配置不改写，终态不可复活，重连不重复，两个监听器验证已开始的派发和后续旧通知的区别 |
| A2 生命周期 | close 跳过远端 DELETE，错误路径不统一，初始化产生伪状态变化 | 已知地址（包括正文失败/迟到）只清理一次；探测、请求头、正文和建连超时均有结果；POST 未发出、结果未知、已登记句柄分别验证，无地址不发送 DELETE；OPTIONS/POST/应答/PATCH 真实失败按顺序通知，不漏发或把原生错误直接交给调用方 |
| A3 信令 | 索引 0 丢候选、索引冒充 MID、空候选格式错误、遗漏作用域；本地 restartIce 未完成协商 | 验证非数字 MID、会话/媒体 ICE 凭据、收集结束与批量 PATCH；仅当前尝试能协商，传输恢复走唯一重连路径 |
| A4 信令 | OPTIONS 不检查状态、Link 解析脆弱、400 非 JSON 丢状态、406 和 5xx 分类不准；认证未贯穿 PATCH/DELETE、Basic 拼入 undefined、相对 Location 用错基准 | 验证混合 Link、缺头、错误正文、401/403/404/406/5xx、受信同源会话认证与跨来源不转发；DELETE 非成功可诊断但不重连；浏览器与双服务端互通通过 |
| A5 信令 | 视频探测和 offer 的 RTP 编码不一致，合成应答属性缺失，七声道 multiopus 映射不一致，负载类型分配重复 | 同一描述和分配逻辑驱动探测与 offer；核对 MID/DTLS 与声道映射，区分不支持和探测故障，浏览器确认探测结果 |
| A6 媒体 | streamless / 音频先到导致误拒；元素解绑遗漏；过时 play/定时器可恢复旧播放；用户暂停被可见性覆盖；VIDEO_ERROR 恢复不可达 | 测试无 stream、迟到视频与确无视频、50% 可见性、手动暂停优先、迟到 play 无效、宿主接管后旧实例不写元素、视频 mute/ended/替换和有字节无帧、归属解绑、局部恢复次数与耗尽后只发 play:failed、保持传输；自动播放被拦时不静音、不重连，需调用方恢复 |
| A7 媒体 | getStats 无效样本被当作零、多流只取最后一条、迟到样本触发重连、调度节流用错度量且更新间隔会重置到期时间 | 假时钟与延迟统计验证：不重叠、不采纳旧样本，按报告计数，有效零增量才判断停滞，单独的停滞不改状态、不发 POST 或 restart，统计挂起可降级，前后台切换重新建基线，稳态和启动期都遵循计划节奏 |
| A8 横切 | 默认值散落、公私事件混用、例行日志过重且生产不可见、诊断缺少原因/时长、名称混淆索引和 MID | 默认值集中、现有类型贯穿；生产能看到脱敏的结构化故障，且诊断不影响时序；命名随归属修正，不做无关改名 |
| A9 发布 | NodeNext 声明无法解析；构建会改源码；打包可能缺失或包含旧产物；README/JSDoc 示例、脚本、事件和错误清单过期 | 干净环境生成并检查实际 tarball；NodeNext 和 bundler 消费测试通过；构建前后源码不变；公开文档示例和接口一致 |

每批独立评审和验证，先过对应验收再推进；保留可回退的分批提交，不保留两套内部生命周期实现。A1/A2 增验首次连通前超时与 ICE failed 交错只报告一次且不重试、连通后失联才重连；A6 增验原因码、最后视频轨道结束与替换、play() 成功但尚未出帧。测试工具选型、时序参数与实测服务端版本记录在验收记录；未执行的验证不作为通过。
